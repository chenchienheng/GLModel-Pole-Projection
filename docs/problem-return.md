# Problem Return

Status: Candidate / Return Template / No Runtime

## Core

Operational issues should return as abstract system improvements, not as private details.

## Template

```yaml
Problem_Return:
  date: "YYYY-MM-DD"
  role: "owner / operator / maintainer"
  screen:
  issue_type:
  impact:
  temporary_fix:
  needed_change: "UI / Gate / Schema / Permission / Template / Training"
```

## Red Doors

- Real-world context stays human-based.
- Pattern return is not raw data storage.
- Candidate fix is not runtime change.
